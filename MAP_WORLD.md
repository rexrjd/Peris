# PERIS continental world

The strategic map is a deterministic 200 × 200 grid: 40,000 fields, each 128 logical units, spanning [-12,800, 12,800) on both axes. Field coordinates are signed integers from -100 to 99. One mainland and three coastal islands contain 23,677 land fields; 16,323 fields are sea. Seed and dimensions are shared between client and server. Continental coastlines and biome scales follow the smaller bounds. Original campaign coordinates and twelve starting positions are preserved inside the central province.

The strategic view is a real Three.js scene with a tilted orthographic camera. Original code builds continuous low-poly terrain, sculpted mountain ridges, coastal banks, shallow rivers, cultivated plots and ground-following roads from the canonical geography. Trees, grass and rocks use instanced geometry. Village, landmark and army models are assembled from original primitives and batched by material. Close views show up to 48 detailed nearby non-owned models, alongside visible owned models; wider views use instanced markers with screen-space thinning. This rendering cap is independent of the server's public entity limits and is not a multiplayer load-test result.

Controls:

- Drag the landscape or use the arrow keys to pan. Wheel zoom stays anchored to the pointer; a two-finger pinch stays anchored to its midpoint and supports panning.
- Hold Q/E or use the rotate buttons to turn the camera. +/− and the zoom buttons change scale.
- H/Home focuses your settlement, F/Army focuses the current army position, and 0/the overview button shows the whole world. Click or drag the minimap to navigate.
- Select a field, village, army or campaign landmark to open its real inspector. March previews a connected land route and its travel time before issuing the existing movement command. Escape cancels marching and closes the selection.
- Layers toggles the field grid, region names and nearby resource potential. These overlays start off. Its Find a field action opens signed X/Y search from -100 to 99; Explore regions moves the camera to a chosen realm.
- Campaign opens the restoration trail, recommendations, rewards and original six campaign encounters. The campaign rail starts collapsed; the legion status card opens your army inspector.

The selected field shows landscape and resource potential; production still comes from settlement buildings. The inspector retains training, movement, route, cooldown and readiness guards. The mobile inspector docks below the map, and the march countdown remains visible.

Land armies use deterministic eight-neighbor A* with no sea crossings or diagonal corner cutting. Routes use exact start/end positions and arc-length interpolation. Detached islands remain inspectable but cannot be reached by a land army. Naval travel is not implemented. Existing campaign and real-time tactical battles remain available.

The scene camera converts between projected terrain and the same signed logical coordinates used by selection, routes and server visibility. WorldCanvas and WorldScene consume the existing RenderState/RenderActions contracts; presentation never mutates the simulation or replaces server authority. Army positions and route previews use the shared movement code and server-adjusted clock. Terrain height, roads and decorative meshes do not change field walkability or travel rules.

If WebGL initialization fails, WorldCanvas creates a fresh canvas and switches to the existing 2D compatibility renderer. Camera rotation and 3D scenery are available in the WebGL view. A lost WebGL context pauses the scene and requests a reload. Tactical battles continue to use their existing Canvas 2D renderer and troop atlases.

The geography guide generated by scripts/render-world-guide.mjs covers all 200 × 200 fields in a 1600 × 1600 PNG. See ARTWORK.md for the current procedural scene and MAP_ART.md for earlier map assets and generation prompts. Generated low-poly preview images are art-direction references only; they are not runtime map backgrounds. The retained illustrated overview can appear in the minimap and 2D compatibility view. Three.js is distributed under MIT; its license copy is public/licenses/three.txt.

Online private snapshots include the player's authoritative assets and active battle participants. Public rival villages and armies are paged by viewport through peris_map_snapshot, capped at 600 of each, with truncation indicators and global player counts. Private resource values are excluded from public village DTOs. Filtered realtime subscriptions and debounced viewport polling avoid downloading the entire shared world on every update.

The database upgrade removes the twelve-player ceiling. A fresh world provides 1,495 valid land spawn sites, preserving the twelve original sites and spacing additional sites four cells apart. Existing installations retain every historical spawn ID and coordinate; new accounts select only currently walkable sites. Capacity on an upgraded world depends on its retained sites and occupancy. This is spawn capacity, not a verified concurrency claim. One settlement and one army per player remain the current rules. Multiple village founding, alliances, trade, siege, conquest, ships and autonomous server battle workers require subsequent gameplay work. No thousand-player load test or remote deployment has been performed.

## Build and database workflow

1. Change canonical geography in src/features/map/domain/worldGrid.ts.
2. Run npm run build:world to regenerate the 5 kB server walkability mask.
3. Run npm run build:sql to regenerate complete installation/upgrade bundles.
4. Run npm run check:world, npm run check:sql, npm test, npm run test:db, npm run test:fresh and npm run build.

For an existing database, apply supabase/UPGRADE_TO_V8.sql once reviewed. It preserves existing players, settlements, army coordinates, route data and all historical spawn sites. Before shrinking a former 400 × 400 world, the transaction checks settlement positions, army start/target positions and saved route waypoints. Any position outside [-12,800, 12,800) aborts the entire upgrade with an explicit manual migration error; no positions are moved or deleted. Plan that migration explicitly before retrying. Existing in-bounds positions are preserved even if the resized coast changes their terrain, so a stranded land army may also need a deliberate migration. Use supabase/FRESH_INSTALL_V8.sql only on an empty database. This change includes SQL artifacts but does not apply them to the live Supabase project. Online routed marches require map metadata version 3, 200 columns, 200 rows, cell size 128 and seed 98213. Incompatible continental deployments block movement with upgrade guidance; older starter deployments retain compatible starter behavior.

Route waypoint coordinates, length, neighboring cells, corner cuts, ownership and battle/training guards are validated by peris_march. The server overrides the supplied start with the current authoritative army position and computes distance and timestamps. Older move_army calls delegate through a validated sampled route. Local campaign saves retain the peris-campaign-v6 key and version 6 format. Import/export preserves legacy 400-world coordinates and saved routes unchanged, checking their geometry against either the current or original coastline. New movement uses the 200-world bounds. An old solo army outside these bounds remains in the save and must be deliberately migrated to use the resized map; importing does not relocate or reset it.

Map-owned rendering and geography can evolve independently from tactical troop art. The active scene starts at src/features/map/rendering/WorldCanvas.tsx and rendering/three/WorldScene.ts. SceneCamera.ts owns projection, picking, anchored zoom and camera movement; landscape.ts owns continuous ground, water and instanced scenery; models.ts owns batched village, landmark and army meshes. WorldView.tsx owns the campaign, Layers, field search and inspectors. MapRenderer.ts and terrain.ts remain the 2D compatibility/minimap paths. Domain rules live in worldGrid.ts, pathfinding.ts, movement.ts and commands.ts; online state remains in OnlineEngine.ts and supabase/modules/map/*.sql. Active source is root src; historical nested copies were not changed.
